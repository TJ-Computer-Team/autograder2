Rules
Do NOT submit malicious code with malicious intent to the grader. Do NOT attempt to exploit any aspect of this system, including but not limited to, accessing unauthorized admin privileges, accessing private user information, etc. If we find out any misuse, you will be disqualified from participating in TJCT competitions, events, and also reported to our sponsors.

Furthermore, please follow all rules given when taking contests on this system. Perhaps there will be collaborative contests, but unless otherwise stated, contests are individual. All aspects of the TJHSST honor code apply.

In general, please note what you can and cannot do for contests. These are subject to change.
  1. You ARE allowed to use templates and pre-written data structures. We acknowledge that in-houses are short on time and having pre-written code can make the process much less tedious.
  2. You ARE allowed to use reference sources online such as language specific documentation. General algorithm guides such as GeeksForGeeks are allowed if the guide doesn't completely solve the problem.
  3. You are NOT allowed to consult intelligent sources such as ChatGPT or other generative AI, or any human sources, during a contest.
  4. You are NOT allowed to discuss problem details until the allotted time window for the contest is over.

During any in-house competition, we will be actively monitoring submissions for plagiarism or use of generative AI and will manually review any code that appears suspicious. Submissions flagged for plagiarism may result in disqualification from future in-houses and travel competitions.

Thank you for your cooperation.

Intro to CP & In-Houses
Competitive programming contests involve competitors submitting a single file (.cpp, .py, .java, etc.) that accepts input and prints output from/to the system. A tutorial on how this works on codeforces.com is located here. This grader, maintained by Computer Team officers, functions in a similar manner to the Codeforces contest system.

We host contests (in-houses) on this site. Some are rated and others unrated. Rated contests impact your overall standing, which is used to calculate rankings for travel competition team selection to represent TJ. Other variables in the ranking calculation include your USACO division and Codeforces rating. Dates for in-houses are in the schedule in the public Google Drive.
Rankings Formula
All data is taken from this grader website.

Codeforces — the max rating your account has reached.

USACO — each division maps to a rating: Bronze / Not Participated → 800, Silver → 1200, Gold → 1600, Platinum → 1900.

In-houses — you get a rating for every rated in-house: 
1200 × (N − rank + 1) / N + 800
where N is the number of participants. This linearly maps rank to a rating in the interval (800, 2000]. If you do not participate, you get a 0.

Your overall in-house rating is the average of your ratings with max(0, min(2, #contests − 2)) drops. So after 3 contests your lowest score is dropped, and after 4 your lowest two are. Problem setters get one extra drop for each rated contest they have authored.

Index — a 0.2 / 0.35 / 0.45 weighted average of your USACO, Codeforces, and in-house values, sorted so your higher values are weighted more.

Problem setters who have to drop every rated contest they took instead get a 0.4 / 0.6 weighted average of USACO and Codeforces, weighting the higher value more.
Travel Competitions
The in-person competitions we are very likely to send teams to are Widener, Code Quest, PClassic, UMD HSPC, VCU HSPC, and UVA HSPC. If there are others you think we should attend, let us know. Application forms are posted on Discord a few weeks before each competition. Details below are based on past years and may change.

By default you are not allowed to use electronic tools for anything besides typing code or viewing documentation, and pre-written code is not allowed.

Widener — at least 3 teams of 3, one of which is a freshman team. There is no online judge; you run input/output locally through VSCode, Eclipse, etc. on your own computer (one per team). To submit you raise your hand, they come to your table, give you one or two inputs as tests, and check the output. One submission per problem, plus one extra submission overall. No web browsers, internet, or other electronic devices.

Code Quest — teams of 3, 4 in-person and 4 online teams, one laptop per team, novice and advanced divisions.

PClassic — one contest in the fall and another in the spring. Teams of 4, no limit on number of teams, one laptop per team, classic and advanced divisions. Templates and pre-downloaded code are allowed.

UMD — teams of 4, we send 1 team. One laptop is provided, and you must use Java.

VCU — teams of 4, we send 2 teams. Two laptops are provided.

UVA — teams of 3, we send 3 teams, one of which is a freshman team. One laptop is provided per team.
Verdicts
Accepted (AC) — Congratulations! Your submission passed all our tests.

Wrong Answer (WA) — Try again! Your submission failed a test and thus didn’t solve the problem correctly. You will not be able to see what the input you failed on was unless it was the first one. Try creating and debugging on edge cases to catch the error.

Compilation Error / Runtime Error — Your code encountered an error. Check the feedback, which may provide more detailed comments. This means your code does not follow the rules of the programming language and did something illegal.

Time Limit Exceeded (TLE) — Your code was too slow. Try reducing time complexity or optimizing your code. Note that our servers can only run around 109 operations a second. The default time limits are 1 second for C++, 2 seconds for Java, and 3 seconds for Python.

Memory Limit Exceeded (MLE) — Your code used too much memory. Store less information. The default memory limit is 256 megabytes.

Running / Compiling — Your code is currently being judged, and the verdict updates live as it runs each test. If it hasn’t finished for a couple of minutes, our servers probably encountered an error. Try resubmitting. If that doesn’t work, please let us know.

Submissions
Your code should take input from standard in (the terminal) and output to standard out (the terminal). This can be done through cin/cout (C++), input() (Python), or Scanner (Java). You can use online documentation to figure out the specifics. You should use your own IDE or text editor to write solutions before uploading the file or pasting it into the submission page. We recommend ide.usaco.guide.

Java users can name the class anything; just put main in the public class. We encourage you to use Python or C++, though.

Example code to sum an array (for more help, consult usaco.guide/general/input-output):

Java 
import java.util.*;
import java.io.*;

public class Main {
    public static void main (String[] args) {
        Scanner scanner = new Scanner(System.in);
        int n = scanner.nextInt();
        int[] a = new int[n];
        for (int i = 0; i < n; i++) {
            a[i] = scanner.nextInt();
        }
        long sum = 0;
        for (int i = 0; i < n; i++) {
            sum += a[i];
        }
        System.out.println(sum);
    }
}
C++ 
#include <bits/stdc++.h>

int main() {

Python 
n = int(input())

print(sum(a))
Standings
Standings are determined by your total points, where each problem solved rewards a set amount of points, and ties are broken by penalty. The penalty for a solved problem is the number of minutes taken to solve it plus 5 minutes for each submission made to it. Your overall penalty is the sum of your penalty for each solved problem. The numbers in the columns for each problem denote the number of submissions taken to solve the problem, and are negative if the participant has not solved it.
